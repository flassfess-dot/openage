именно в её очередь и создаёт юнита после завершения обучения.

больше не вызывает удалённый обход правил. Он заполняет её обычными платными

4. ПРОВЕРКА АВТОСОХРАНЕНИЯ ОХВАТЫВАЕТ КАНОНИЧЕСКОЕ СОСТОЯНИЕ

Файлы: prototype/scripts/background_autosave.gd,
prototype/scripts/simulation_snapshot.gd.
Вместо ограниченного списка полей акторов сверяются все сущности и разделы
канонического состояния, включая месторождения, пути, туман, технологии,
экономику, карту, правила и состояние контроллера. Временные поля выбора
и производные кэши формаций исключены, как в обычном каноническом снимке.
Сверка не меняет живые сущности. Записи препятствий без ID тоже учитываются
по отдельности и не затирают друг друга.

Для периодической сверки используются движковые value-hash полных записей
и разделов, затем SHA-256 компактного результата. Это лёгкая проверка совпадения
состояния, а не криптографическая гарантия отсутствия коллизий каждого раздела.
Отдельная проверка SHA-256 байтов checkpoint сохранена. Полный детерминированный
world_state_hash по-прежнему строится из канонического состояния.

Новые регрессии подтверждают изменение проверки при расходе дерева 100 -> 25,
изменении пути, разведки, технологии и первого из двух препятствий без ID.
test_autosave_archive.gd прошёл с несколькими последовательными записями,
новыми приказами, перезапуском фонового процесса и отменой активной записи.

Контрольное измерение на 5000 синтетических записях ресурсов: около 96 мс
для периодической сводки против около 4,9 с для полного JSON-хэша в том же
запуске. Это локальный микрозамер, а не обещание времени кадра на всех картах.

5. РУЧНОЕ СОХРАНЕНИЕ ИСПОЛЬЗУЕТ АТОМАРНУЮ ЗАМЕНУ

Файл: prototype/scripts/game_save_archive.gd.
После записи, flush и закрытия .tmp все записи используют существующую нативную
атомарную замену. Прежний слот больше не перемещается в .bak перед публикацией.
Старый аргумент atomic_replace оставлен для совместимости вызовов, но передача
false также сохраняет атомарную запись.

Для уже случившихся прерываний старого протокола read() ищет .bak, если основной
файл отсутствует, и применяет обычную полную валидацию архива. Каталог сохранений
показывает такой слот по исходному пути; имеющийся основной файл не дублируется
резервной копией. Существующий повреждённый основной файл не подменяется молча.

Новая регрессия проверяет повторную запись, false-аргумент, состояние «нет
основного файла, остались валидный .bak и оборванный .tmp», обнаружение слота
в меню, повторную запись восстановленного слота и отсутствие дублей.
