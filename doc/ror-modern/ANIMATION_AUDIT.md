# Аудит классов анимации прототипа

Дата проверки: 2026-09-10.  
Задача: R-003 из `doc/DEVELOPMENT_PLAN.md`.

## Проверенный источник

- параметры графики: `prototype/assets/generated/gamespec-prototype.json`;
- фактически доступные кадры: `prototype/assets/generated/*.png`;
- правила направлений: `openage/convert/entity_object/export/metadata_export.py`;
- runtime-каталог: `prototype/scripts/resource_catalog.gd`.

SLP-направления определяются для каждого клипа из его собственных `angle_count`, `mirroring_mode`, `frames_per_angle` и числа экспортированных кадров. Порядок не переносится между классами неявно.

Формат `15×5` означает 15 кадров на сохранённое направление и 5 сохранённых направлений. Логических направлений у проверенных клипов восемь; направления 5–7 получают кадры 3–1 с отражением.

## Зафиксированные ограничения

1. Урон сейчас наносится по таймеру в симуляции, а не на `damage_frame`.
2. Стрела Archer не создаётся на `projectile_release_frame`.
3. Смерть мгновенно скрывает юнита; death/decay не проигрываются.
4. Gather использует состояние `work`, но соответствующие кадры не импортированы.
5. Смена состояния знает только idle/move/attack и не имеет формального AnimationController.

Ни один отсутствующий класс нельзя заменять копией другого клипа или обратным порядком кадров. Его необходимо добавить в одноразовый импорт из исходных DRS/SLP и описать собственным GraphicDescriptor.
